# Design

구현에 참고할 현재 설계 문서를 모아둔다.

설계 문서는 날짜보다 주제명으로 관리한다.

예:

- `notification-service-overview.md`
- `notification-domain-model.md`
- `notification-sync-flow.md`
- `notification-status-policy.md`

## What Goes Here

- 서비스가 맡는 문제와 맡지 않는 문제
- 초기 범위와 나중에 다룰 범위
- 도메인 모델 설계
- 상태 전이
- API flow
- 정책 초안
- 구현 전 설계 메모
- 필요한 다이어그램

## Rule

설계 문서는 완성된 정답이 아니라 현재 구현을 안내하는 기준이다.

구현과 관찰 결과에 따라 설계가 바뀌면 문서를 함께 업데이트한다.

되돌리기 비용이 큰 아키텍처 결정은 `docs/decisions/`에 별도로 남긴다.
